# PledgePack: 100 Goals to Production Readiness

**Purpose:** ROADMAP.md's own "Known Gaps" section admits PledgePack is feature-complete but **not yet production-ready**, citing supply-chain security, CI coverage, documentation accuracy, and test reliability. This document replaces that vague admission with 100 concrete, verifiable goals, grounded in a direct source-code audit (2026-09-15), organized into 10 execution phases.

**Governing rule for this document:** a goal may only be marked `✅ Resolved` once it has a **passing, CI-enforced regression test** proving it — not a self-report. Several items in `LIMITATIONS.md`/`ROADMAP.md` are currently marked "✅ Resolved" despite the underlying code being a stub, a no-op, or unenforced in CI (see Phase 0). That pattern is the root problem this document exists to fix.

**North stars:**
1. **Genuinely production-ready** — correct, secure, reliable, performant, honestly documented.
2. **Works anywhere** — as a standalone generic bundler *and* as PledgeStack's bundler backend, on every platform it claims to support.

Status legend: 🔴 open · 🟡 in progress · ✅ resolved (test-enforced) · 🚨 open, and a regression test now proves a real bug exists (worse than 🔴 — a known, reproduced failure, not just unimplemented)

## Suggested execution order

Phases are ordered by dependency and risk, not arbitrarily:

- **Phase 0** must go first — it's currently unknown whether CI is even honestly green, and several "done" claims are false. Everything else is easier to trust once this is fixed.
- **Phase 1 (Security)** next — the CORS and fake-signing issues are real, exploitable-today gaps, not future risk.
- **Phases 2–4** (optimizer correctness, plugin consolidation, resolver) are the deepest engineering work and the actual technical differentiators worth getting right before more surface area is added.
- **Phases 5–7** (packaging, dev server, PledgeStack integration) are the "works anywhere" north star made concrete — do these once the core engine underneath them is trustworthy.
- **Phases 8–9** (testing discipline, docs/governance) are ongoing practices, not a one-time pass — but codifying them now prevents this exact gap (feature-complete docs, unverified reality) from recurring.
